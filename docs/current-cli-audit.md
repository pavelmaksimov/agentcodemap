# codenav CLI: фактическое поведение

Проверено 2026-08-28 на версии `0.1.0`, commit `c0b2f11`. Первичный прогон commit
`67c8ce3` обнаружил сломанный `graph`; во время аудита появился одноимённый fix,
после которого команда и все 32 теста были перепроверены. Документ основан на
реальных запусках CLI, тестах и чтении реализации, а не только на обещаниях
`README.md`.

## Что это за инструмент

`codenav` использует Tree-sitter, чтобы возвращать агенту не целые файлы, а
структурные срезы: карту символов, исходник одного символа, контекст изменённых
строк, совпадения регулярного выражения и эвристические связи между символами.

Внутри есть два основных пути выполнения:

```text
outline / diff / grep
    -> прочитать явно заданные файлы
    -> parse_file(...)
    -> ParsedFile / Entity / Slice

symbol / impact / graph
    -> просканировать весь --root
    -> RepoIndex
    -> поиск и связи по коротким именам символов
```

Номера строк везде начинаются с 1; конечная строка диапазона включительна.
Язык обычно определяется по расширению файла.

## Быстрый агентский маршрут

В текущем интерфейсе агенту приходится выполнять несколько независимых команд:

```bash
# 1. Получить карту файлов и координаты символов
codenav outline src --lines

# 2. Найти кандидатов по регулярному выражению
codenav grep 'render_outline' src

# 3. Прочитать выбранный символ
codenav symbol render_outline --root src

# 4. Посмотреть эвристические входящие и исходящие ссылки
codenav impact render_outline --root src

# 5. Получить контекст конкретного diff
git diff | codenav diff src/codenav/outline.py --diff -
```

`graph` можно использовать после `impact`, но его рёбра остаются именной
эвристикой и требуют проверки по исходнику.

## `outline`: компактная карта символов

```text
codenav outline PATH... [--lines] [--lang LANG]
```

Файл разбирается напрямую. Для каталога выполняется рекурсивный обход: скрытые
каталоги и значения из `RepoIndex.SKIP_DIRS` пропускаются, а файлы выбираются по
известным расширениям. Модули без извлечённых символов не печатаются.

Реальный вывод:

```text
$ codenav outline src/codenav/outline.py
src.codenav.outline:
A LETTERS

F module_name

F render_outline
```

`--lines` существенно полезнее для агента, потому что результат сразу становится
адресуемым:

```text
$ codenav outline src/codenav/outline.py --lines
src.codenav.outline:
A LETTERS  L9-9

F module_name  L12-17

F render_outline  L20-62
```

`--lang` переопределяет определение по расширению. Без него файл с неизвестным
расширением завершает работу с кодом 1 и подсказкой `pass --lang`; с
`--lang python` тот же файл успешно разбирается.

Ограничения:

- порядок файлов при обходе каталога явно не сортируется;
- имя модуля строится удалением расширения, поэтому `sample.py`, `sample.ts` и
  `sample.go` получают одинаковый заголовок;
- явный файл не проверяется на существование заранее;
- у этого пути нет лимита 512 KiB, который используется в `RepoIndex`.

## `diff`: структурный контекст изменённых строк

```text
codenav diff PATH (--diff FILE|- | --lines SPEC) [--lang LANG]
```

`--lines '10,15-20'` задаёт строки явно. `--diff FILE` читает unified diff из
файла, а `--diff -` — из stdin. Из diff используются только добавленные номера
строк на новой стороне.

Каждая непустая изменённая строка расширяется до наименьшего содержащего её
символа. Изменение атрибута расширяется до метода/функции или класса. Соседние
диапазоны с зазором не более 5 строк склеиваются.

Реальный вывод для строки 12:

```text
$ codenav diff src/codenav/outline.py --lines 12
### L12-17  [function module_name]
12  def module_name(file_path: str) -> str:
13      base = file_path
14      if base.startswith("./"):
15          base = base[2:]
16      base = os.path.splitext(base)[0]
17      return base.replace(os.sep, ".").replace("/", ".").strip(".") or "<module>"
```

Значимые особые результаты:

```text
(no slices)
src/codenav/outline.py: NEW MODULE (2 added lines, not sliced)
src/codenav/outline.py: MODULE DELETED (not sliced)
```

Ограничения:

- `--diff` и `--lines` не объявлены взаимоисключающими; если передать оба,
  молча побеждает `--diff`;
- полностью удалённые строки не дают структурного среза;
- один вызов обрабатывает только один `PATH`, даже если diff многофайловый;
- неверный `SPEC` приводит к необработанному `ValueError`;
- при склейке нескольких соседних символов заголовок сообщает только одно имя.

## `symbol`: исходник найденного символа

```text
codenav symbol NAME [--root DIR]
```

`RepoIndex` рекурсивно сканирует `--root`, пропускает скрытые/служебные каталоги
и кодовые файлы больше 512 KiB. Поиск принимает короткое имя или суффикс
квалифицированного имени, например `RepoIndex.impact`.

Реальный вывод:

```text
$ codenav symbol _parse_lines_spec --root src/codenav
### _parse_lines_spec  (src/codenav/cli.py:30-39, function)
30  def _parse_lines_spec(spec: str) -> set[int]:
31      """'10,15-20' -> {10, 15..20}"""
...
39      return out
```

Если совпадений несколько, команда без предупреждения печатает только первый
символ в порядке обхода файлов. Проверка на двух файлах с одинаковой функцией
выбрала первый файл. Стабильного идентификатора определения в выводе нет.

Встроенная верхнеуровневая справка расходится с parser: она обещает
`symbol NAME [PATH...]` и `--impact`, но дополнительные `PATH` отвергаются с
кодом 2, а флага `--impact` нет.

## `impact`: эвристические связи символа

```text
codenav impact NAME [--root DIR] [--detailed]
```

Команда печатает две группы:

- `depends-on` — определения, на которые ссылается цель или её поддерево;
- `dependents` — сущности, содержащие обращение к цели.

Для member-символов учитываются квалифицированные обращения и известные типы
receiver-а; bare-name fallback используется только для уникального имени.

Строковые литералы длиной до 500 символов тоже сканируются, чтобы замечать
forward annotations и DI-записи вида `"pkg.mod:Symbol"`; docstring стараются
исключать. `logger` жёстко исключён как шумный символ.

В обычном выводе пути не печатаются: выводятся только отсортированные и
уникальные ID объектов. `--detailed` добавляет путь, строки и тип сущности.

Фрагмент реального вывода:

```text
$ codenav impact render_outline --root src/codenav
impact chain for render_outline:
- depends-on:
Slice.start_line
Slice.end_line
Entity
module_name
LETTERS
- dependents:
cmd_outline
```

С `--detailed` строка сущности выглядит так:

```text
codenav/cli.py:113-122::cmd_outline function
```

Связи являются подсказками, а не доказанным call graph. Разрешение не учитывает
полную семантику импортов и областей видимости. Неоднозначные bare-имена
отбрасываются, поэтому результат консервативнее, чем полный call graph.

## `grep`: regex-совпадения, сгруппированные по символам

```text
codenav grep PATTERN [PATH...] [--full] [--lang LANG]
```

Без `PATH` сканируется текущий каталог. Регулярное выражение применяется к
каждой строке. Совпадения группируются по наименьшей содержащей сущности;
остаток печатается как module-level блок.

Обычный режим печатает только совпавшие строки:

```text
$ codenav grep render_outline src/codenav
src/codenav/cli.py
119         outline = render_outline(parsed.entities, path, with_lines=args.lines)
---
src/codenav/cli.py
27  from codenav.outline import render_outline
---
src/codenav/outline.py
20  def render_outline(entities: list[Entity], file_path: str, with_lines: bool = False) -> str:
```

`--full` заменяет совпавшие строки полным исходником каждого найденного символа.
Это полезно для небольших функций, но не имеет ограничения размера и может
резко увеличить ответ.

Ограничения:

- при отсутствии совпадений команда возвращает код 0 и вообще ничего не печатает;
- неверное regex и отсутствующий явный файл дают полный traceback;
- блок не сообщает имя, вид и диапазон найденного символа отдельными полями;
- module-level блок добавляется после блоков сущностей, поэтому порядок не всегда
  совпадает с порядком строк файла;
- нет лимита результатов, пагинации или признака усечения.

## `graph`: цепочки влияния

```text
codenav graph NAME [--root DIR] [--nodes N] [--max-paths K]
```

Ребро `A -> B` означает, что тело `A` ссылается на `B`. Связи разрешаются тем же
qualified/type-aware анализом, что и у `impact`: короткое имя используется только
для однозначного символа. Алгоритм строит входящие и исходящие простые пути через
цель. `--nodes` ограничивает длину каждой цепочки, не их общее количество;
`--max-paths` отдельно ограничивает число выбранных цепочек. Внутри также есть
защитные пределы: не более 2000 перечисленных путей и 20 соседей на узел.

Каждая цепочка в default-режиме содержит не более 3 узлов:

```text
$ codenav graph render_outline --root src/codenav
render_outline:
cmd_outline -> render_outline -> Entity
cmd_outline -> render_outline -> module_name
```

Изменение `--nodes` сокращает или расширяет каждую цепочку вокруг целевого
символа. Оно не расходуется между разными цепочками:

```text
$ codenav graph render_outline --root src/codenav --nodes 3
render_outline:
cmd_outline -> render_outline -> Entity
cmd_outline -> render_outline -> module_name

$ codenav graph render_outline --root src/codenav --nodes 8
render_outline:
main -> cmd_outline -> render_outline -> Entity -> end_line
main -> cmd_outline -> render_outline -> Entity -> file
main -> cmd_outline -> render_outline -> Entity -> name
main -> cmd_outline -> render_outline -> Entity -> start_line
main -> cmd_outline -> render_outline -> module_name
```

`--max-paths 1` оставляет только первый выбранный путь. Для известного изолированного
символа выводится `__version__: no influence data (0 paths)`.

Текстовый формат всё ещё выводит только короткие имена, без файлов и стабильных
идентификаторов. После ограничения `--nodes` одинаковые видимые пути удаляются;
разные определения с одинаковыми короткими именами всё ещё могут выглядеть
одинаково.

## Языки: загрузка грамматик и качество outline

Успешно загрузились все заявленные режимы: Python, JavaScript, TypeScript, JSX,
TSX, Go, Rust, Java, Scala, Ruby, PHP, C#, C++ и C. При холодном кэше пакет
`tree-sitter-language-pack` может пытаться создать lock и скачать грамматику,
что важно для изолированного агента.

Минимальные файлы каждого языка были прогнаны через
`codenav outline ... --lines`. Наблюдаемое качество:

- Python, TSX, Java, Scala и C# — ожидаемые основные определения извлечены;
- TypeScript — type/interface/constant/function найдены, метод интерфейса не показан;
- JavaScript — определения найдены, но у класса появился лишний `C <unknown>`;
- Go — функция названа, но `const` и `type` получили `<unknown>`;
- Rust — имена найдены, но `struct Runner` и `impl Runner` показаны двумя классами;
- Ruby — основные имена найдены вместе с лишними `C <unknown>`;
- PHP — функция и класс найдены, метод класса пропущен;
- C++ — класс найден, имена метода и свободной функции стали `<unknown>`;
- C — имя функции стало `<unknown>`.

Поэтому «язык поддерживается» сейчас означает «грамматика доступна и файл можно
разобрать», но не гарантирует одинаковую полноту символов и связей.

## Коды завершения и диагностический контракт

Фактическое поведение неоднородно:

- `0` — успех; также пустой `grep` и `(no slices)`;
- `1` — ожидаемая доменная ошибка через `sys.exit`, но также необработанный
  exception с traceback;
- `2` — ошибка разбора аргументов `argparse`.

Нет стабильных кодов ошибок, JSON-объекта ошибки, версии схемы, статистики
просканированных/пропущенных файлов или общего признака неполного результата.
Предлагаемый агентский контракт описан в `agent-interface-design.md`.
